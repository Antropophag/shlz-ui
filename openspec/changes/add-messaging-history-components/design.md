## Context

Wave 12 established `Messages.svg` and `History of changes.svg` as independent visual authorities and proved that no reusable implementation existed at that baseline. Planner Schedule has since shipped separately. The repository already provides framework-neutral CSS modules and semantic primitives such as Avatar, File Row, and Document Row. This change introduces two independent presentation modules and deliberately does not combine them into a generic activity-feed domain.

## Goals / Non-Goals

**Goals:**

- Provide small semantic markup interfaces with substantial source-backed layout, responsive, overflow, and state behavior hidden in CSS.
- Preserve plain HTML/PHP and framework consumption without a rendering runtime.
- Compose existing primitives without duplicating their contracts.
- Make Message Thread and History Timeline independently auditable and releasable.

**Non-Goals:**

- Rich-text Composer, editor commands, message transport, delivery/read state, realtime synchronization, reactions, moderation, or attachment lifecycle.
- Audit-log policy, sorting, filtering, persistence, permissions, or live updates.
- A full Messages or History application screen, framework adapter, or shared domain model.

## Decisions

### 1. Keep two independent modules

Message Thread and History Timeline have separate interfaces, styles, manifests, documentation, fixtures, consumers, and evidence. Similar actor/timestamp/attachment content is composed from existing primitives rather than abstracted into a new shared public seam.

### 2. Use native list markup as the external seam

Consumers author `<ol>` or `<ul>` structures with documented classes. CSS owns alignment, grouping, connector paint, wrapping, and responsive behavior. This keeps server rendering natural and makes DOM order the accessibility and chronology/message-order contract.

History Timeline period labels stay in the flat list as presentational `<li role="presentation">` wrappers. The visible label inside each wrapper has a stable consumer-owned `id`, and every following entry in that period references the label with `aria-describedby`. This keeps period labels out of the timeline-entry count while preserving an explicit accessible association without introducing nested-list layout semantics.

### 3. Ship no behavior controller

Both modules are presentational. Consumer-authored links and buttons retain native behavior. A controller would be shallow because the source establishes no reusable interaction beyond reading and native activation.

### 4. Keep all business and temporal semantics consumer-owned

The library never calculates chronology, parses dates, infers the current actor, maps delivery/read state, sanitizes content, or assigns business meaning. Consumers provide visible labels and accessible names; CSS state hooks are presentational only.

### 5. Reuse existing primitive contracts by composition

Avatar and file/document rows may appear inside either module, but remain independent occurrences with their own markup and audit identity. The new root manifests classify nested primitive dependencies without inheriting their evidence.

### 6. Faithfully translate source geometry without copying application shells

`Messages.svg` governs message rhythm, alignment, surface paint, author/time hierarchy, and attachment placement. `History of changes.svg` governs timeline rhythm, marker/connector geometry, and content hierarchy. Exact values are promoted only when repeated and semantically local; application canvas widths and raster screenshot geometry remain evidence, not tokens.

### 7. Bound performance and responsive claims

The modules are non-virtualized presentation lists. Evidence covers representative bounded datasets, long localized content, narrow widths, text scaling, focus, and page-overflow prevention. Infinite lists and windowing require a separate contract.

## Risks / Trade-offs

- Static source does not prove runtime semantics → prefer native lists and consumer-authored labels; claim no live behavior.
- Similar metadata may tempt a generic feed abstraction → keep modules independent until two real adapters prove a shared seam.
- User-authored rich content can overflow or be unsafe → provide containment styles while keeping sanitization explicitly consumer-owned.
- Nested primitives can blur audit counts → use stable root IDs and occurrence manifests with explicit nested dependencies.

## Migration Plan

The change is additive. New CSS entrypoints and documented markup require no migration. Rollback removes the new exports, fixtures, consumers, manifests, and evidence without changing existing primitives or design sources. It also restores or removes the nine legacy Playwright baseline artifacts regenerated by this integration so the retained screenshots continue to match the rolled-back consumer markup.
