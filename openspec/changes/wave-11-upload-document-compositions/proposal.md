## Why

Upload / Document compositions remain `INVENTORIED` even though File Row and Document Row were independently verified in Wave 5. Wave 11 must establish the higher-level source-to-primitive boundary and an honest composition-only audit disposition without inferring an unsupported upload lifecycle or promoting the application-specific Detailed appeals screen into a public contract.

## What Changes

- Inspect `Documents.svg` and `Detailed appeals.svg` as the sole visual authorities for Document, Upload-Drag, Description Files, Small document, Attached Document, and Drag and Drop Document compositions.
- Census and classify every repository-local composition root, implementation, consumer, fixture, diagnostic, native substitute, and local alternative, distinguishing higher-level compositions from verified File Row and Document Row dependencies.
- Add an independent Upload / Document compositions manifest, source-to-primitive ledger, inventory reconciliation, and Wave 11 report with exact evidence applicability and limitations.
- Add mutation-sensitive source-integrity and repository-census evidence without adding upload behavior, transport, persistence, new package exports, or a generic public component API.
- Keep `shlz-design-source/` unchanged and retain Wave 5 status for File Row and Document Row.

## Capabilities

### New Capabilities

- `application-compositions/upload-document-compositions`: Source-defined upload/document composition boundaries, primitive reuse classification, repository-wide occurrence classification, and evidence required for an independent composition-family disposition.

### Modified Capabilities

None.

## Impact

The change affects OpenSpec planning, a new component-audit manifest, the project inventory, focused source/census tests, and the Wave 11 audit report. It adds no file-selection, drag/drop, validation, progress, retry, preview, removal, transport, persistence, form-integration, or public package contract; authoritative SVGs remain read-only.
