## Why

The adaptive harness begins at execution planning, so short intentions for substantial new capabilities can reach OpenSpec with material product decisions still implicit or can force users to pre-write a specification. Add an interview-first requirements readiness layer that resolves only genuinely user-owned ambiguity before packet planning while preserving the lightweight direct route.

## What Changes

- Insert repository inspection, impact routing, decision ownership, and a deterministic requirements readiness gate before adaptive execution planning.
- Persist minimal recoverable decision provenance and execution authorization without creating a second normative specification.
- Synthesize resolved requirements into OpenSpec and support default approval stops, explicit pre-authorization, and requirements re-entry when apply discovers material ambiguity or scope expansion.
- Add deterministic guards, fixtures, and smoke evaluations for the ten required workflow scenarios and the non-implementing GitHub Pages retrospective fixture.
- Update agent-facing routing and OpenSpec skills so the new layer is one continuation of the existing harness rather than a parallel workflow engine.
- Preserve direct execution for trivial, implementation-only, and fully determined work.

## Capabilities

### New Capabilities

- `harness/requirements-readiness`: Decision ownership, targeted interview, readiness, durable recovery, OpenSpec synthesis, authorization, and apply re-entry behavior before adaptive execution planning.

### Modified Capabilities

None. The new capability composes with the execution-planning contract introduced by the completed adaptive harness change; it does not redefine packet behavior.

## Impact

The change affects `AGENTS.md`, OpenSpec/skill routing documentation, repo-local `openspec-*` skills, the `tools/harness.mjs` CLI and its focused tests/fixtures, and operational state under `docs/exec-plans/`. It does not publish GitHub Pages, alter the showcase runtime, create a generic product-management system, or change `shlz-design-source/`.
